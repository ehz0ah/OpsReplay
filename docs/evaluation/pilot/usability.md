# Usability and interview

Use the standard ten-item System Usability Scale after both core conditions and the
brief product tasks. Use 1 strongly disagree to 5 strongly agree, plus a separate
unanswered value. Keep the scale direction consistent. Ask for an immediate response
before the interview. The source says to use the centre point when a respondent cannot
choose; voluntary skipped items stay missing and are not imputed by the facilitator.

| Item | Statement                                                                                  | Polarity |
| ---- | ------------------------------------------------------------------------------------------ | -------- |
| 1    | I think that I would like to use this system frequently.                                   | Positive |
| 2    | I found the system unnecessarily complex.                                                  | Negative |
| 3    | I thought the system was easy to use.                                                      | Positive |
| 4    | I think that I would need the support of a technical person to be able to use this system. | Negative |
| 5    | I found the various functions in this system were well integrated.                         | Positive |
| 6    | I thought there was too much inconsistency in this system.                                 | Negative |
| 7    | I would imagine that most people would learn to use this system very quickly.              | Positive |
| 8    | I found the system very cumbersome to use.                                                 | Negative |
| 9    | I felt very confident using the system.                                                    | Positive |
| 10   | I needed to learn a lot of things before I could get going with this system.               | Negative |

For a complete standard response, odd items contribute response minus 1. Even items
contribute 5 minus response. Multiply the sum by 2.5 to get 0 to 100. This is a usability
scale value, not a percentage or learning score. Do not impute missing items. With only
5 to 10 participants, report individual scores and the median with sample size.

Reference: J. Brooke, “SUS: A quick and dirty usability scale,” in _Usability Evaluation
in Industry_, Taylor & Francis, 1996. Wording and scoring were checked against
[the AHRQ-hosted source](https://digital.ahrq.gov/sites/default/files/docs/survey/systemusabilityscale%2528sus%2529_comp%255B1%255D.pdf)
on 20 October 2026. The source states that SUS is freely available for usability
assessment if published reports acknowledge it. Questionnaire copyright: Digital
Equipment Corporation, 1986. No paid instrument or competitor study was copied.

## Interview

- Which part was hardest to understand or operate? Show the point if possible.
- What evidence changed your diagnosis?
- What did the debrief explain clearly, and what remained unclear?
- Did playback help you understand your actions? Give an example.
- Was anything misleading, missing or unnecessary?
- What differed between investigation and reading the static case?

Ask for examples. Do not lead with “Was playback useful?” or promise an expected answer.
Record defects separately from preferences. A quote alone does not establish improved
learning. Remove names and private command content before using quotations publicly.

## Brief product tasks

1. Find and read the Free lesson “Safe recovery starts with evidence.” Locate its
   related Challenge. Record completion and navigation help.
2. Open “Apply a proxy configuration change,” flag a risky line, write a concern,
   submit, read the released findings and find the saved result in history.

Run these after learning questions because the lesson and review can reveal recovery
principles. These are usability tasks only. No assistant task is included in the core
pilot. Provider accuracy and latency are measured separately with synthetic cases.
